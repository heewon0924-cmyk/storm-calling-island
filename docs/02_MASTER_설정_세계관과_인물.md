# 1. 작품 개요

## 제목
**「폭풍을 부르는 섬 이야기」** [확정]

제목의 의미는 두 가지다.
1. 실제로 폭풍이 몰아치는 섬과 사건
2. 과거의 사건을 다시 세상에 끌어내는 사람들

## 장르
현실 기반 미스터리 / 추리 / 탐정, 다중 시점 서사, 심리적 긴장감이 중심인 어두운 분위기. [확정]

초자연적인 현상보다는 **사람의 거짓말, 기억, 이해관계, 은폐된 사실**을 중심으로 사건을 구성한다.

## 핵심 컨셉 — "같은 사건, 다른 진실"
하나의 사건을 여러 등장인물의 관점에서 조사한다. 각 캐릭터는 서로 다른 직업과 인간관계, 과거를 가지고 있기 때문에 동일한 사건을 보더라도 가지고 있는 정보가 다르다.

시스템 설계 원칙은 [01_게임_시스템_설계원칙.md](./01_게임_시스템_설계원칙.md)를 참고.

# 2. 시대적 배경 [확정 방향]

현재와 달리 스마트폰과 인터넷이 일상적으로 사용되지 않는 시대. 다만 통신 자체가 불가능한 시대는 아니다.

## 통신의 특징
* 일반 전화 사용 가능
* 무선통신 가능
* 기상 상황 등에 따라 통신이 불안정할 수 있음
* 모든 통신이 완전히 끊기는 것은 아님

### 중요한 설계 원칙
**"통신 불가"가 아니라 "통신을 믿을 수 없는 상황".**

따라서 누군가가 무선통신을 시도했다는 사실 자체가 사건의 단서가 될 수 있다.

# 3. 전체 이야기의 시작

세계적으로 유명한 전설적인 배우가 있다. 배우는 전성기이며 아직 젊고, 엄청난 인기와 사회적 영향력을 가지고 있다.

그런 배우의 과거 연인이었던 유명 여배우가 자신의 집에서 살해된다. 배우는 가장 유력한 용의자 중 하나가 되지만, 경찰은 결정적인 증거를 확보하지 못한다. 결국 공식적인 혐의를 적용하지 못하고 사건은 미해결 상태로 남는다.

## 배우의 실종
경찰 조사가 끝난 뒤 배우는 자신의 집으로 돌아간다. 그런데 이후 갑자기 사라진다.
* 은퇴 선언 없음
* 작별 인사 없음
* 명확한 행방 없음

배우가 왜 사라졌는지는 전체 이야기의 핵심 미스터리 중 하나다.

## 초대장
시간이 흐른 뒤 약 8명의 사람에게 **배우의 이름으로** 초대장이 전달된다. 목적지는 배우가 소유한 **개인 섬**. 초대받은 사람들은 모두 과거의 사건과 서로 다른 방식으로 연결되어 있다.

그러나 **정작 배우 본인은 배에 없다.**

초대받은 사람들은 배우의 개인 섬으로 향하는 전용선(크루즈)에 탑승한다. 그리고 섬으로 향하던 중 **섬의 관리인 Richard Bennett가 살해된다.**

# 4. CASE 구조

## CASE 1
**사건:** 전용선에서 Richard Bennett 살해

핵심 질문 세 가지:
1. **누가 Richard Bennett를 죽였는가?** → CASE 1에서 해결한다.
2. **Richard Bennett와 죽은 여배우는 어떤 관계였는가?** → CASE 1에서 중요한 단서가 드러난다.
3. **Richard Bennett는 왜 죽어야 했는가?** → CASE 1에서 완전히 해결하지 않는다. 최종적인 답은 CASE 2 또는 이야기 후반부에서 밝혀진다.

즉 플레이어가 CASE 1을 끝내면서 "아, Richard가 이걸 알고 있었기 때문에 죽였구나." 정도까지는 이해할 수 있지만, "그렇다면 왜 과거의 일을 그렇게까지 숨겨야 했는가?"라는 더 큰 의문은 CASE 2로 이어진다.

## CASE 2
배우의 개인 섬에서 별도의 사건이 발생한다. CASE 2를 통해 다음이 서로 연결된다.
* Richard의 과거
* 섬에서 발생했던 오래된 사건
* A. Morgan의 정체
* 여배우 살인사건의 진실
* 배우가 사라진 이유
* Richard가 반드시 제거되어야 했던 이유

## CASE 1 ↔ CASE 2의 관계 [중요 원칙]
**CASE 1의 범인과 CASE 2의 범인이 반드시 같을 필요는 없다.** 여배우를 죽인 사람 역시 별개의 인물일 수 있다.

세 사건(여배우 살인사건 / Richard의 죽음 / 과거 섬 사건)이 서로 다른 범인에 의해 발생하더라도, 그 배경에는 **하나의 오래된 사건과 그 사건을 덮기 위해 쌓인 거짓말**이 존재할 수 있다.

## 두 사건의 연결 흐름
```
CASE 1: Richard Bennett 살인
   ↓
Richard와 여배우의 관계 발견
   ↓
여배우가 죽기 전 섬에 관련된 행동을 했다는 사실 발견
   ↓
A. Morgan과 연결
   ↓
개인 섬으로 이동
   ↓
CASE 2: 개인 섬에서 발생하는 별도의 사건
   ↓
CASE 1에서 발견한 단서들이 과거 사건과 연결되며 전체 진실이 밝혀짐
```

* **CASE 1 피해자**

## Richard와 여배우의 관계

특히 여배우가 배우의 개인 섬과 관련된 행동을 했을 가능성이 있다. **정확한 내용은 [보류].**

* 표면적인 이유: 섬의 관리인으로서 초대객들을 직접 맞이하기 위해.
* 실제 이유: **이번 초대와 관련해 확인해야 할 과거의 문제와 A. Morgan에 관한 정보를 확인하기 위해.** 정확히 누구를 만나려 했는지는 [보류].

# 7. A. Morgan — 핵심 미스터리

## 현재 확정된 방향
**A. Morgan은 실제 인물 한 명이 아닐 가능성이 높다.**

오래된 섬 기록에서 반복해서 등장하지만 공식적인 인물 기록이 없다. 더 중요한 점:
* 기록마다 필체가 다름
* 여러 사람이 같은 이름을 사용한 흔적
* 특정 사건의 책임자로 반복해서 등장

즉 A. Morgan은 실제 사람이라기보다 **책임을 떠넘기기 위해 만들어진 가상의 책임자 / 희생양**에 가깝다.

처음에는 작은 사건의 책임을 피하기 위해 만들어졌지만, 시간이 지나면서 여러 사람이 서로 다른 목적으로 같은 이름을 사용하게 된다.

예: 자신의 실수를 숨기기 위해 / 다른 사람을 보호하기 위해 / 돈이나 이익을 위해 / 과거 사건을 은폐하기 위해

**작은 거짓말들이 쌓여 거대한 거짓말이 된다.**

---

# 8. 과거 섬 사건

배우가 유명해지기 전 발생한 사건. 폭풍이 몰아치던 밤 여러 사람이 섬에 있었다. 한 사람이 크게 다치거나 사망한 것으로 공식 기록에 남았다.

공식적인 설명: **악천후로 인한 사고**

하지만 실제 상황에는 여러 가지 모순이 있다.
* 사고 시각이 맞지 않음
* 일부 사람의 행적이 기록에서 사라짐
* 누군가의 이름이 공식 기록에서 삭제됨
* 여러 사람이 서로 다른 작은 거짓말을 함
* 사고 현장에서 중요한 물건이 이동됨
* A. Morgan이라는 가상의 책임자가 만들어짐

당시 사건의 진실을 알고 있는 사람들이 각자 일부만 기억하거나 숨기고 있다.

# 9. 폐기된 설정 [폐기]

> **"Richard Bennett가 배의 지배인(선박 관리자)이다."**

현재 설정과 다르다. 정확한 설정은:

> **Richard Bennett = 배우의 개인 섬에서 원래부터 근무하던 지배인이며, 초대객들을 맞이하기 위해 배에 탑승했다.**

그리고:

> **Michael Grant = 배우의 오랜 매니저 = 초대객 = 생존**

# 10. CASE 1 — 사건 개요

## 사건 장소
배우의 개인 섬으로 향하는 크루즈(전용선). [확정]

## 피해자
Richard Bennett — 배우의 개인 섬 지배인. 원래 섬에서 지배인/관리자 역할을 하던 사람으로, 이번 초대 손님들을 맞이하기 위해 배에 탑승했다가 CASE 1에서 살해된다.

## 기본 사건 흐름
8명의 초대객이 배에 탑승한다. 배우는 나타나지 않는다. Richard Bennett가 섬의 지배인으로서 손님들을 맞이한다. 이후 폭풍이 심해지고 통신에 문제가 발생한다. 그리고 Richard가 자신의 방에서 사망한 채 발견된다.

상세 시간표는 [03_CASE1_MASTER_TIMELINE.md](./03_CASE1_MASTER_TIMELINE.md), 인물별 동선은 [04_CASE1_인물동선표.md](./04_CASE1_인물동선표.md) 참고.

### 현장 특징
* 명확한 강제 침입 흔적이 없음
* 큰 몸싸움의 흔적이 없음
* Richard의 개인 노트가 사라짐
* 여러 사람이 사건 전후의 행동에 대해 거짓말함

## CASE 1의 거짓말 구조
**중요한 설계 원칙: 거짓말 = 범인이라는 공식이 아니다.**

8명 대부분이 무언가를 숨기고 있을 수 있지만, 그 이유는 서로 다르다.

예: 과거를 숨기기 위해 / 배우를 보호하기 위해 / 자기 자신을 보호하기 위해 / 명예·직업을 지키기 위해 / 다른 사람을 보호하기 위해 / 과거 사건의 책임을 피하기 위해

따라서 플레이어가 거짓말을 발견할 때마다 범인을 좁혀가는 동시에 **잘못된 추론에 빠질 수 있어야 한다.**

## CASE 1 MASTER 설계 원칙
가장 중요한 제작 원칙이다.

1. **먼저 MASTER TRUTH를 만든다.** 캐릭터별 정보를 먼저 만들지 않는다. 먼저 작가만 알고 있는 "그날 실제로 무슨 일이 있었는가?"를 완성한다. MASTER에는 실제 시간 / 실제 장소 / 실제 이동 경로 / 실제 행동 / 실제 대화 / 실제 살해 과정 / 실제 범인 / 실제 증거 / 각 인물이 실제로 목격한 것을 전부 기록한다.
2. **그 다음 캐릭터별 KNOWLEDGE를 만든다.** MASTER를 완성한 뒤 각 캐릭터에 대해 직접 본 것 / 들은 것 / 알고 있는 것 / 추측하는 것 / 오해하고 있는 것 / 숨기는 것 / 거짓말하는 것을 분리한다.
3. **마지막으로 게임 플레이 정보로 변환한다.**

```
MASTER
  ↓
캐릭터별 실제 지식
  ↓
플레이어에게 공개되는 정보
  ↓
조사 / 대화 / 증거
  ↓
플레이어의 추리
```

이 순서를 유지한다.

# 11. 플레이어 선택 시스템 방향 [보류]

질문 시스템의 두 방향은 [01_게임_시스템_설계원칙.md](./01_게임_시스템_설계원칙.md) §8을 참고. 현재는 B 방식(단계적 해금)이 더 적합하다는 의견이 우세하나 최종 확정하지 않았다.

## 잘못된 추리의 처리
게임오버만으로 처리하지 않는다. 플레이어가 잘못된 판단을 내리면:
* 특정 인물이 플레이어를 신뢰하지 않게 됨
* 이후 정보를 얻지 못할 수 있음
* 특정 캐릭터가 이후 사건에서 이탈할 수 있음
* CASE 2의 진행 방식이 달라질 수 있음
* 플레이어가 일부 진실에 접근하기 어려워짐

**즉, 플레이어의 판단 자체가 사건의 역사가 된다.**
